# secret-mask

A Claude Code mod (function-hook plugin). `README.md` is the user-facing spec; keep it in step with any behavior change in the same commit.

## Layout

- `hooks/detect.ts`: pure detection. Known values (`Rules.values`), the vendor-format patterns (token prefixes, PEM blocks, bearer headers, URL passwords), one parser per assignment format (dotenv/shell, INI, YAML, JSON, CLI flags), `envSecrets` (which environment variables count), patterns-file parsing and validation, the allow-list, and `findSecrets(text, rules)`, which returns non-overlapping spans. No `$`, no I/O.
- `hooks/corpus.test.ts`: the standing detection corpus, one row per input (format, text, the exact values to mask, everything else byte-identical). Every past review repro is a row. A detection change adds rows first.
- `hooks/vault.ts`: pure masking and restoring over a `Vault` (the value-to-placeholder mapping). `maskText`, `maskBlocks` (session.append content), `maskDeep` (a tool's structured result), `restoreFields` (tool-call input). Tokens come from a `mint` function the caller passes, so tests are deterministic.
- `hooks/policy.ts`: config parsing, the per-tool restore policy, the command parser, status and self-test text.
- `hooks/register.ts`: wiring. The hooks, the command, the patterns-file read, `$.state` for the on/off override. Holds the vault in a closure created by `register` (module memory, never `$.state`).
- `types/index.d.ts`: the mod's types and its `$.state` contract (`PluginState['secret-mask']`).
- `.claude-plugin/plugin.json`: manifest and `userConfig` options. `marketplace.json` makes the repo its own marketplace.
- `scripts/check.sh`: the commit gate (validate, test, typecheck).
- `.claude-plugin/types/` and `tsconfig.json` are generated by Claude Code when it loads the mod from a watched folder. They're gitignored; don't commit or hand-edit them.

## secret-mask design invariants

The stage bar is raised: this mod is security-sensitive. A failure that looks like success (a secret reaching the model or the transcript unmasked while the person believes it is masked, a placeholder restored somewhere it should not be, the mapping reaching disk or a log) is a blocker.

- **Three sources, in this order of trust** (README "What gets masked" is the contract; the parsers are judged against its list, and anything off the list is out of contract, not a bug):
  1. Known values: secret-named environment variables (omp's `SECRET_ENV_PATTERNS` rule, value at least 8; connection-URL passwords raw and percent-decoded), patterns-file `secrets`, and every value sources 2 and 3 have found. Matched literally, also inside larger tokens.
  2. Vendor formats: anchored prefixes and shapes only.
  3. Assignments in a stated list of formats, one parser each, all sharing `isSecretName` for names and `looksLikeReference` for values. Line formats anchor at line start. JSON is handled only where `JSON.parse` accepts the text.
- **Why there is no generic assignment regex.** v0.1's single `SECRET_VALUE` regex recognised `NAME=value`, `name: value`, `"name": "value"` and `--name=value` anywhere in any text. Three review rounds found six blockers in it, each fix moving the edge (nested values dropped, `token_count` overmasked, `_PASSWORD` missed, a JSON number swallowing its `}` vs a dotenv `}`): one regex serving five syntaxes has no correct value boundary. omp (oh-my-pi) has the rule "No generic keyword/entropy rules: a coding agent must still be able to read identifiers like `token_expiry_seconds`" (`src/secrets/patterns.ts`) and gets its arbitrary secrets from exact known values (the environment, `secrets.yml`). This mod follows it and keeps a bounded per-format assignment layer on top, because tool output is where it learns most values. Don't add a cross-format rule or an entropy rule; add a format with its own parser and corpus rows.
- **The environment is read once per load** with `$.process.run(['/usr/bin/env', '-0'])` (`$.env.get` can't enumerate names), NUL-separated so multi-line values parse. Its output goes straight to `envSecrets` and is never logged, stored or reported; only counts reach status. A failed read is reported in status and masking continues with the other sources.
- **The mapping never leaves module memory.** The vault lives in a closure `register` creates. It is never put in `$.state` (any plugin reads any value there, and other plugins can hook `state.set`), `$.store` (a JSON file on disk), a log line, a toast, a status line, command output or a deny reason. Only kinds and counts are reported.
- **Hot reload, restart and `--resume` drop the mapping.** Placeholders issued before then can no longer be restored. A tool call that needs one is denied with a reason that says so; it never runs with the placeholder text in place of the secret. The `/secret-mask on|off` override is in `$.state` and survives a reload. `/clear` keeps the vault (it is memory only and placeholders stay stable).
- **Placeholders** are `__SECRET_<KIND>_<8 uppercase hex>__`: ASCII word characters only, so a placeholder that reaches a shell unrestored is inert text. The hex is random (`crypto.getRandomValues`), checked against the vault for collisions. The same value always gets the same placeholder within a load. KIND is at most 24 characters. Masking is idempotent: placeholders this vault issued are never rescanned. Text that only looks like a placeholder gets no protection and is scanned for known values and patterns like any other text.
- **Two passes per unit.** A unit is every string of one row (`maskBlocks`) or one tool result (`maskDeep`). Pass one registers every candidate the patterns find in the whole unit, overlapping ones included (a URL password inside a secret assignment), and settles nothing (each string is scanned whole, so a JSON document holding an issued placeholder still parses, dropping candidates that overlap one, and between issued placeholders as before); pass two replaces every literal occurrence of every known value, the earliest and then longest span winning where they overlap. A value found in one field or block is then masked in all of them, before and after where it was found.
- **Mask everywhere the API lets a mod rewrite**, main conversation and subagents alike (no `agentId` early return): every `session.append` door (the backstop: it is what the model reads and what the transcript file stores), `prompt.submit` text (so the queue record and the prompt row agree), the tool's structured result at `tool.call` (what the screen draws and the transcript's `toolUseResult` keeps), `session.send` text, `prompt.attachment` text (what the model reads for an `@file` or reminder; the transcript keeps the engine's raw record of the attachment, which no hook can rewrite), and `prompt.context` blocks. Known values are replaced literally before the patterns run, so a restored secret echoed back is masked again even where no pattern matches it.
- **Restore only where the policy says** (`restoreFieldsFor` in `policy.ts`): Bash, PowerShell and Monitor `command` always; Write/Edit/NotebookEdit content only with `restoreIntoFiles`; MCP tool string arguments only with `restoreInMcp`; never Agent/Task prompts, SendMessage or anything else. Restoring happens on the way down in `tool.call`, so permission checks, the auto-mode classifier and PreToolUse hooks see the real value (documented in the README).
- **Fail closed where it matters.** `session.append`'s `.catch` replaces the row's writable text with a fixed withheld marker. `tool.call` withholds the whole result (`{ deny: WITHHELD }`) when masking it throws, and its `.catch` denies whether or not it had called `next` (never replays a raw result). `prompt.attachment` and `prompt.context` answer the marker; `prompt.submit` drops the prompt; a saved output file is overwritten with the marker. The vault holds at most `MAX_SECRETS` (10,000); past that, masking throws and the above applies.
- **One KIND contract** (`KIND_SOURCE`, `isKind` in `detect.ts`): a pattern name normalises to a KIND or is refused at load; minting checks the issued placeholder against it; restoring treats every reserved-shape token (`__SECRET_<anything>_<8 hex>__`) not in the vault as unknown and denies. An unknown or unrestorable placeholder in a restored field denies the call.
- **Off** stops masking new content. Restoring placeholders already issued continues, so work in flight does not run commands with placeholder text.
- **Errors and saved outputs** (found live, 2.1.310): an errored tool result's record is stored as made, so `tool.call` answers `{ deny: <masked text> }` after `next` when it holds a secret (the record then holds the masked text). Core writes an output too large to keep inline to `<session>/tool-results/<file>` before any hook runs; `tool.call` masks the file a result's `persistedOutputPath`/`rawOutputPath` names, never a path taken from output text, and only where `$.fs.stat(path, { resolve: true }).realPath` is a file directly in `<projects root>/<dir>/<this session id>/tool-results/`, the projects root (`$CLAUDE_CONFIG_DIR` or `~/.claude`, plus `/projects`) resolved the same way (`isSessionToolResult`). A link out of the folder, another session's folder or a forged suffix is refused and logged. The file is overwritten with `WITHHELD` right after it is read and before masking starts, then with the masked (or original) text, so losing the hooks worker mid-mask leaves the marker (R4-1, found live: a 3.99 MB output with 10,000 distinct keys took 11.8 s to mask, the engine respawned the worker at its 5 s heartbeat, and the cleanup died with it). Masking time is now linear in the text: known values are replaced in one pass of a longest-first alternation, and known values are found in one alternation pass too (R5-4). Embedded-JSON scans: mid-line documents must close on their line; line-start documents share a budget of 16 passes, and running out throws `JsonScanIncomplete`, which the hooks withhold like any masking failure (R5-3: an exhausted scan once counted as coverage). Worst shape measured: 0.25 s for 4 MB. A file we may rewrite but can't read, mask or write back is overwritten with `WITHHELD` (the engine refuses `$.fs.read`/`write` over 4 MiB and has no ranged read, so a saved output over 4 MiB, or one whose masked text grows past it, is withheld rather than masked); if that write rejects too, `maskPersisted` throws and `tool.call` answers `{ deny: WITHHELD }`.
- **@-mentions are refused, not masked, on disk** (`prompt.mention`, before `next`): the engine stores an attachment's raw payload whatever `prompt.attachment` answers. A text file holding a detectable secret or a known value is denied with a value-free reason; a text file that can't be read, can't be stat'ed for any reason but ENOENT (`isMissingPathError`), or is over 5 MB is denied (fail closed); media and missing files pass. Off with `refuseSecretMentions: false` or masking off.
- **Managed plugins can bypass it** (found live): a managed `prepend`-tier plugin passed `prompt.context`, one startup `session.append` and (in a review run) `prompt.attachment` past user plugins. A mod can't see an event it never received; the README says so.
- **No personal or employer patterns in the repo.** Fixtures use obviously fake keys (`FAKE`, `EXAMPLE`, `0000`). Personal patterns go in the user's patterns file outside the repo.

## Commands

```sh
scripts/check.sh            # claude plugin validate . && claude plugin test . && typecheck
scripts/check.sh --no-tsc   # when TypeScript isn't available
```

All gates must pass before every commit. A behavior change needs a test in `hooks/*.test.ts` (the `claude-code/testing` kit: `mock.clock`, `mock.store`, `mock.env`, and `on(...)` hooks that stand for the engine beneath the plugin) written first and seen failing for the intended reason, then the change that makes it pass.

To try the mod in a live session: `claude --plugin-dir .` (interactive sessions hot-reload on save), or `claude -p --plugin-dir . "<prompt>"` for a headless run (always loads fresh; hooks that need a terminal won't fire). `claude --debug` logs every skipped hook and refused result.

## Design invariants (apply to every mod built from this template)

- **Main conversation vs subagents.** Events from a subagent's loop carry `e.agentId` (`agent_id` on `classic.*` events). Decide explicitly whether the mod acts on subagents; by default return `next(e)` early for them.
- **Hot reloads reset module variables** (timers included). `register` and `session.start` run again; `$.state` and `$.store` survive. Anything that must persist goes in state or store. Change an atom's `shape` tag when its stored type changes.
- **Never throw out of a hook or timer for reporting.** Logging, status and toasts are best effort. A hook that guards (denies a tool call, drops a prompt) gets a `.catch` that decides fail-open or fail-closed deliberately (`next.called ? next(e) : { deny }`).
- **Headless sessions** (`e.isInteractive === false`, `claude -p`) have no terminal: no panes, `$.ui.notify` fails, `$.session.compact` rejects. Skip or degrade explicitly.
- **Cost and the prompt cache.** Anything that calls a model (`$.model.complete`, `classify`, `fork`, `$.agent.spawn`) is billed to the person. Say what it costs in the README, bound it with options, and don't change the system prompt or tool list per turn (that rewrites the whole prompt cache).

### Engine constraints found the hard way (Claude Code 2.1.29x–2.1.310)

- `$.prompt.submit` is refused from inside a `command.run` hook (it would wait on the turn the hook holds). Submit from a `$.clock.after(0, …)` timer.
- `$.session.compact` rejects while a turn runs and in headless sessions.
- A plugin's submitted prompt never expands `@` mentions; `$.prompt.fill` lets the person send it instead.
- `$.model.fork` replays the main thread's last request, which ends before the turn's final answer: quote the answer into the fork prompt if the fork needs it.
- The engine already prefixes `$.ui.status`, `$.ui.toast` and command output with the plugin name; don't add `secret-mask:` there. `$.ui.log` lines keep the prefix.
- A model `Write` outside the project raises a permission prompt; have the plugin write its own files with `$.fs.write` (it creates directories). `$.fs.write` replaces the whole file; there is no append.
- `turn.step` hooks are async generators in the path of every request: always pass the stream through (`yield* next({ ...e, effort })`). A rewritten `model` must be a full id (`claude-haiku-5-5`); an alias failed with `unrecognized_model`. Changing `effort` per request keeps the prompt cache (Opus, Sonnet, Haiku 5.5); changing `model` rereads everything uncached. The UI keeps showing the session's model and effort, so surface a rewrite with `$.ui.status`.
- `tool.call`: `const r = await next(e); return { ...r, context: [text] }` adds text the model reads after the tool result and the person never sees; `{ deny: reason }` blocks the call. A `tool.call` hook without `.catch` is reported by validate as a gate: give it one that fails open or closed on purpose.
- Haiku 5.5 rejects `temperature`/`top_p`/`top_k`, `budget_tokens` and assistant prefill with a 400. Prices step up 5x above 100K prompt tokens.
- Side calls (forks, completions, subagents, compaction) use the "everything else" prompt-cache bucket (5m on a subscription), not the main conversation's 1h one. Cache reads still count against plan usage.
- Text a hook injects for the model must not talk about the model's thinking or reasoning ("you can't see it", "doesn't count"): Opus 5.5's reasoning-extraction safeguard refused such a request. Phrase it in terms of the reply and the work.
- Don't build on instructions the model can ignore: a gate that "asks" the model to do something first failed live. Enforce in a hook, or give the model the information and let it decide.
- `/clear` is `session.end` with `reason: 'clear'` and no `session.start` after it: reset per-conversation state there.
- `$.process.run` is logged in the debug log by executable, argument count, exit code, time and output size (`/usr/bin/env with 1 args ...`, `exited 0 in 4ms, 4345 + 0 chars`), never its output (checked live on 2.1.310). Startup needs no permission prompt.
- `$.fs.stat` rejects with a `HooksError` whose message ends in the errno (`<plugin>: $.fs.stat(<path>) failed: ENOENT`, `... failed: EACCES`, `... failed: ENOTDIR`) and carries no `code` (checked live on 2.1.310). The test kit's message for a mock `{ deny: 'ENOENT' }` is `<plugin>: $.fs.stat: ENOENT`, so match the trailing `: ENOENT`.

### Bugs that recur in these mods (check every change against them)

Reviews of relay, defer-queue and prewalk kept finding the same family: a boolean flag left stale by a late event (track the running `turnId` instead), a message lost on a path nobody tested (a refused submit, a release racing a new hold), a timer or async step acting for a run that was cancelled or replaced (guard with a `runId` and re-check after every `await`), state that survived `/clear` or a reload when it shouldn't (or didn't when it should), and engine state copied into the mod's own flags (decide from facts at decision time). Two review rounds of blockers in the same mechanism means change the mechanism.

### Test kit notes

- A hook that answers an op on `$` (`command.register`, `fs.read`, `model.complete`, `ui.toast`, `session.messages`) returns `{ value }` or `{ deny }`; a hook that answers an event (`session.start`, `turn.start`, `turn.complete`) returns the event's result directly.
- One bottom hook per event per test file (a second registration errors). Test files with JSX are `.test.tsx`.
- Use `mock.clock(on)` and `clock.advance`/`settle` for time; there is no `setTimeout`.
- A throwing mock hook is skipped rather than surfacing its error, so test decisions that depend on an error's text as pure functions in `policy.ts`.
- Any helper that receives `$` must be a top-level function: the engine's static check refuses a module that passes `$` to a closure defined inside `register`. `atom({ plugin, key })` takes string literals, not a const.
- The kit accepted a wrong tool-input shape at runtime that `tsc` caught: run the typecheck.

### Live checks

The test kit stands in for the engine; it can't show what the engine really does. Before building on an engine behavior the types don't state, probe it: a throwaway observer mod (`--plugin-dir`) that logs events with `$.fs.write`, and one short live session, with `--model haiku` to keep it cheap. Record the Claude Code version a behavior was checked on. Headless runs (`claude -p`) create transcript folders under `~/.claude/projects/`; run them from a scratch directory.

## Conventions

- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`).
- Bump `version` in `plugin.json` for every release users should get. Every install, one from a local-clone marketplace included, runs a copy made at install time under `~/.claude/plugins/cache/`, and `claude plugin update` only replaces it when the version changes, so neither a save nor `/reload-plugins` brings a clone's edits in: bump the version, run `claude plugin marketplace update` and `claude plugin update`, then restart (checked on Claude Code 2.1.311). For live work, run `claude --plugin-dir <clone>`, which reloads on save.
- MIT licensed: `LICENSE` at the root, and `plugin.json` says `MIT`. Treat the repo as public: no secrets, tokens, session IDs, personal paths or employer-specific details in code, tests, docs or commit messages.
- Don't add Claude or AI attribution trailers to commits.
